# 待定任务

## [待定] 断流自动续接（DeepSeek 网页 web API `/chat/continue`）

日期：2026-09-11 · 状态：wire 全部实测完毕（请求 + 响应流），待写 spec + 实施

### 背景

DeepSeek 网页在生成中途断流（`response/status=INCOMPLETE` +
`{"type":"error","finish_reason":"generation_err"}`），网页 UI 显示 Continue 按钮。
v0.2.2 已修 silent 部分：deep.api 识别该信号并报 503（此前把截断当成功返回空回复）。

### wire 实测事实（两轮抓包）

**续接请求**（用户点网页 Continue 时）：

```
POST /api/v0/chat/continue
{"chat_session_id":"<uuid>","message_id":<断流的 response message id>,"fallback_to_resume":true}
```

- **无 PoW**；无 prompt / model_type / parent_message_id
- `message_id` = ready 事件的 `response_message_id` = deep.api 已在跟踪的 `run.parentMessageId`

**续接响应流**（与 completion 同构，同 parser 复用）：

- ready：`response_message_id` = 原 message id（同一条消息续写）
- **快照重发全部既有 fragments**（含断流前已发出的 thinking/response 全文）→
  实现必须按"已发字符数"裁剪快照内容，否则客户端收到重复文本
- 追加增量正常接在最后 fragment 上；终态正常 `FINISHED`
- `auto_resume:false` 不决定 UI（网页实测仍显示 Continue 按钮）

### 设计要点（草案，见 `.research/spike-design.md` 末尾）

- 触发：`streamError.reason ∈ {generation_err, incomplete_status}` + 拿到过 message_id + 未超上限（默认 3）
- 动作：`/chat/continue` + 500ms 间隔 + 不调 PoW
- 合并：同一 parser + skip 参数（只裁快照来源的增量，不裁 appends）
- 上限耗尽仍 INCOMPLETE → 维持 503；`unsupported_client_by_model` 不续接直接报
