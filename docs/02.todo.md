## [待定] 断流自动续接（DeepSeek 网页 web API `/chat/continue`）

日期：2026-09-11 · 状态：wire 行为已实测，待抓续接响应流 + 写 spec

### 背景（已完成的部分 → v0.2.2）

DeepSeek 网页在生成中途断流（`response/status=INCOMPLETE` +
`{"type":"error","finish_reason":"generation_err"}`），网页 UI 显示 Continue 按钮。
v0.2.2 已修 silent 部分：deep.api 识别该信号并报 503（此前把截断当成功返回空回复）。

### 待做：自动续接（替代 503）

用户点网页 Continue 时抓到的请求（已实测）：

```
POST /api/v0/chat/continue
{"chat_session_id":"<uuid>","message_id":<截断的 assistant message id>,"fallback_to_resume":true}
```

- **无 PoW 头**（continue 端点不要求）、无 prompt / model_type / parent_message_id
- 触发判据：`response/status: INCOMPLETE`（+ error 帧）；`auto_resume` 字段**不**决定是否有
  Continue 按钮（实测 `auto_resume:false` 时网页仍显示按钮）
- 设计草案：`.research/spike-design.md` §3（服务端信号触发 + 复用 `/chat/continue` 续接）

### 下一步

1. **抓续接响应流**：点 Continue 后那条 `/chat/continue` 的 SSE 响应（response_message_id
   是否更新、status 终值、内容接续形态）——网页可抓（请求 + 响应都能看到）
2. **写 spec**：`docs/superpowers/specs/` → 设计冻结
3. **走 writing-plans**：出实施计划 + TDD

### 触发条件

- 不紧急；v0.2.2 已消除 silent bug（至少报 503 而不是假装成功）
- 需要用户方便登录网页复现一次断流
