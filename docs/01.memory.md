## 架构关键决策（2026-09-08 实测校正）

1. **认证来源**：chat.deepseek.com 的 localStorage `userToken`（格式 `{"value":"<JWT>","__version":"0"}`），由 MAIN world content script（bridge-main）读取推送，**不是 cookie**（user_token cookie 取不到）。
2. **token 推送**：只有 chat.deepseek.com（及 *.deepseek.com）页面读 token 并推送 `auth.sync`；其他网页只挂 `window.deepApi` 不推 null（否则 popup 登录态闪烁）。SW 收到 null token 且当前有有效 token 时**不清缓存**。
3. **DeepSeek API 头**：只带 `Authorization: Bearer <token>` + `Content-Type: application/json`；**X-Client-*、credentials:include（cookie）会触发 WAF 拦**（返回 SPA HTML/401）。
4. **URL 前缀**：SW fetch base = `https://chat.deepseek.com/api/v0`；adapter 内部路径**不带** `/api/v0`（如 `/chat_session/create`），拼双重前缀会返回 SPA HTML。
5. **响应包装**：session id 在 `data.biz_data.id`；PoW challenge 在 `data.biz_data.challenge`（不是 `data.chat_session.id`/`data.challenge`）。
6. **PoW（DeepSeekHashV1 wasm）调用约定**（对照 RezaParsian/DeepseekPowsolver 实测）：`wasm_solve(retptr, cPtr, cLen, pPtr, pLen, difficulty_f64)`；`__wbindgen_export_0` 是 `malloc(size, align)`（**2 参数**，align=1）；answer 读取是 **f64**（栈偏移 +8）；**status=1 成功、0 失败**；malloc 可能 realloc 内存，每次操作后重取 memory buffer 视图。prefix = `${salt}_${expire_at}_`（expire_at 毫秒）。
7. **SSE 事件格式**（实测）：`{"p":"response/content","o":"APPEND","v":"你好"}` 缩写（path/op/value）；连续增量 `{"v":"！"}` **省略 p/o（继承上式）**；内容路径是 `response/content` 不是 `response/fragments`；usage 是 `{"p":"response/accumulated_token_usage","o":"SET","v":66}`；ready 事件 `request_message_id`/`response_message_id` 在顶层。
8. **completion 请求体**：`{chat_session_id, parent_message_id, model_type, prompt(纯文本), ref_file_ids, thinking_enabled, search_enabled, preempt}`；prompt 是**当前轮用户消息纯文本**（不写 `<｜user｜>` 模板，网页端会显示）；多轮靠 parent_message_id 链。
9. **多轮增量**：SessionMapper mirror 必须含 assistant 回复（`commit` 时并入 `messages + {role:'assistant', content: agg.content}`），否则下一轮 tail 以 assistant 开头被判 rebuild → 新建会话 → 上下文丢失。
10. **popup 心跳**：只向 SW 请求完整 state（`panel.getState`，2s 一次），不直读 storage。
11. **storage 读取**：用数组形式 `chrome.storage.local.get([key])`（单字符串 key 的 await 返回形状不稳定，丢字段）。
12. **CSP**：MV3 默认禁 wasm，manifest 需 `content_security_policy.extension_pages` 加 `'wasm-unsafe-eval'`。

## 经验教训

- 扩展加载目录是 `/Users/xmli/me/code/deep.api/extension/`（构建产物），**不是仓库根目录**；载入前先在 chrome://extensions 移除旧版。
- 版本机制：每次改代码后 `npm run bump`（x.y.z → x.y.(z+1)），构建流程见 README。
- SW 环境 console.log 要打开"Service Worker"链接才能看到；页面 console 只有 bridge-main 日志。
- deep.api 当前版本：v0.1.33（2026-09-08）。
- **模型输出工具调用的形态不确定**（实测至少三种）：标签（含缺左尖括号变体）；代码块包裹的 JSON（[ ]）；**裸 JSON 对象/数组**（整个 content 就是工具调用 JSON，无任何包裹——v0.1.33 用户实测发现）。parseToolCalls 必须三层 fallback 才能稳。
- **DeepSeek 业务响应码**：HTTP 200 + 业务 code 非 0 是常见 token 过期形态。`fetchJson` 必须同时检查 HTTP 状态**和**业务 code，否则会把登录失效误报成误导性的 `id missing`（v0.1.32 修复）。
- **Prompt 工程式工具调用局限**：模型在 `tool_choice:auto` 下**不保证**调用工具（实测有时直接文本回答）。要稳定强制调用需 OpenAI 的 `tool_choice:'required'`（当前未实现）。
- **调用方开关**（v0.1.34）：请求可传 `thinking: bool | null`（覆盖 `thinking_enabled`，null/false 显式关）、`search: bool`（覆盖 `search_enabled`）、`reasoning_effort: 'low'|'medium'|'high'|'max'`（OpenAI 兼容字段，网页端是否生效待实测）。未传时沿用模型默认（flash.thinking=false 保守默认；pro.thinking=true）。
